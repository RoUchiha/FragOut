# Implementation-ready story slices

| ID | User story | Acceptance criteria | Phase |
|---|---|---|---|
| FR-001 | As a collector I can add a precise owned variant by name | Correct brand/flanker/concentration, can confirm/edit; duplicates supported | 1 |
| FR-002 | As a collector I can upload a photo and identify candidates | Server candidate list, exact variant choice, manual fallback, no forced auto-add | 2 |
| FR-003 | As a user I can see a recommendation suited to current weather/time | Actual or explicitly overridden weather, only Owned bottles, explain why | 3 |
| FR-004 | As a user I can pick Gym/Date/Work/Party/Errands quickly | Buttons call working contextual ranking, each uses distinct venue policy | 3 |
| FR-005 | As a user I can personalize and reorder shortcut tiles | Add/edit/hide/reorder/reset, settings persist across sessions | 3 |
| FR-006 | As a user I can request layering and specify my occasion | Combo requires occasion, evaluates 2 Owned bottles and climate | 4 |
| FR-007 | As an enthusiast I can see documented layering sources | Tier label, direct pair, source URLs, last reviewed | 4 |
| FR-008 | As a dupe owner I can substitute appropriately | Version-specific edge, difference notes, downgraded hypothesis label | 4 |
| FR-009 | As a cautious user I can avoid speculative pairings | Evidence-only default, zero-match fallback and explicit opt-in | 4 |
| FR-010 | As a user I can indicate what actually worked | Wear log/feedback adjusts future recommendations but not source truth | 5 |
| FR-011 | As a privacy-conscious user I can use the app without location | City/manual conditions and manual event time; no block | 3 |
| FR-012 | As a user I can delete/export my data | Private account access, retention and deletion verified | 6 |
